# Source Context

## Goal

Use the smallest relevant source set and distinguish verified facts from guesses.

## Rules

1. Read the linked source when the environment has a compatible tool or connector.
2. Prefer primary project sources over summaries when both are available.
3. Extract only information relevant to scope, behavior, ownership, dependencies, and acceptance criteria.
4. State which sources were actually read.
5. If a source cannot be accessed, say so and continue only with available context.
6. Never infer hidden content from a URL title or file name.
7. Avoid flooding the planning context with unrelated source details.

## Verification

Before task breakdown, confirm that important claims in the plan are either supported by supplied context or explicitly labeled as assumptions.
